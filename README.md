# pi-ext

在 Pi 的交互式终端中管理用户级安装的插件包。不卸载包，也不替代 Pi 的加载器。

## 安装

```bash
pi install git:github.com/outmost9271/pi-ext
```

现有会话执行 `/reload` 或重启 Pi，再输入 `/extensions`。已在 Pi 1.6.0 验证。

## 用法

输入 `/extensions` 打开列表。直接键入包名或来源进行搜索；按上下键选择，按回车打开操作菜单。列表显示全局默认值、项目覆盖和按配置计算的状态，不代表本次会话已重载或第三方包已成功初始化。

```text
/extensions enable <包> --global
/extensions disable <包> --global
/extensions enable <包> --project
/extensions disable <包> --project
/extensions inherit <包>
```

`enable` 和 `disable` 必须明确指定且只指定一个作用域。`inherit` 仅作用于当前项目。可用列表中的完整来源消除重名歧义；来源含空格时用引号括起来。保存后可立即重载，也可以稍后使用 `/reload`。

| 全局 | 项目 | 配置有效状态 |
| --- | --- | --- |
| 启用 | 跟随全局 | 启用 |
| 禁用 | 跟随全局 | 禁用 |
| 任意 | 显式启用 | 启用（保留原有资源过滤） |
| 任意 | 显式禁用 | 禁用 |

## 配置与范围

- 管理用户级 `packages` 中的包。禁用覆盖扩展、技能、提示词模板和主题。内置扩展、顶层独立文件、临时加载和仅项目安装的包不在范围内。管理器不能禁用自身。
- 全局设置写到 Pi 用户目录的 `settings.json`；项目设置写到当前工作目录的 `.pi/settings.json`，不会修改父目录或未受信任项目的设置。
- 开关存为 Pi 原生资源过滤器。包条目上的 `x-pi-ext` 元数据只用来记录本次修改和恢复原条目，没有额外状态文件。已有手写项目规则时，`inherit` 会撤销管理器自己的覆盖并恢复原项目规则，不会删除它们。
- 项目显式启用使用独立的 Pi 项目条目，保留当时的包来源和原有过滤规则。远程包可能因此安装一份项目副本，且项目覆盖不会自动跟随全局的版本或资源过滤变化。已有原生增量过滤且无法无损转换时，管理器拒绝显式启用，不覆盖它。
- 如果通过其他工具改动了管理器接管的条目，而旧元数据仍在，管理器会拒绝覆盖该条目。建议先用 `/extensions inherit` 撤销项目覆盖，再用 `pi config` 手动调整。

## 测试

```bash
npm test
PI_BIN=/绝对路径/pi bash test/pi-smoke.sh
```

集成测试在 Linux 上使用 `script` 和 `jq`，用临时设置目录启动 Pi，不修改正在使用的配置。
